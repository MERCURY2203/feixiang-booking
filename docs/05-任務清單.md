# 飛翔球館小程序 · 任務清單（SDD 第 5 步）

2026-11-04

## 怎麼用這份清單

把整個小程序切成 25 個小任務，按順序做。每個任務寫明：做什麼、對應規格書哪一節、怎樣算完成。

- 每次做一個任務，在手機上試，對照「完成標準」和規格書的驗收標準檢查
- 通過了就勾掉，再做下一個；沒通過就先修好，不帶著問題往下走
- 做的過程中發現規格要改，**先改文件、再改程式**

```
0 準備 → 1 地基(T1–T4) → 2 訂場核心(T5–T10) → 3 訂單與退款(T11–T12)
       → 4 活動商品(T13–T15) → 5 管理端(T16–T22) → 6 測試與上線(T23–T25)
```

階段 2 是最關鍵的：防重複賣、付款和到期處理都在這裡，也是上一版 bug 最多的地方。

## 階段 0 · 準備（你來做）

開始寫程式前必須有的兩樣東西，其餘上線清單（備案、支付綁定、企業微信等）可以和開發同時進行。

- [ ] **P1 註冊企業小程序**：用廣州羽美體育發展有限公司的營業執照註冊，拿到 AppID
- [ ] **P2 開通微信雲開發**：安裝微信開發者工具，開通雲開發並先申請半年免費的個人版環境，記下環境 ID

## 階段 1 · 地基

- [ ] **T1 項目骨架和公共樣式**
  - 做什麼：建立客人端 3 個分頁和管理端側邊欄的空框架；配色、卡片、按鈕的統一樣式；全小程序唯一的金額格式化和伺服器時間取得
  - 對應：規格書「頁面地圖」「全局規則」、技術方案「畫面風格」
  - 完成標準：3 個分頁可切換；¥88.5 顯示為 ¥88.50；把手機時間調快，顯示的時間不變
- [ ] **T2 建立數據庫和權限**
  - 做什麼：按技術方案建好 12 張表（含 settings）；設定權限，客人只能看到自己的訂單
  - 對應：技術方案「資料怎麼存」
  - 完成標準：用兩個微信號登入，互相看不到對方訂單
- [ ] **T3 登入、隱私協議和身份識別**
  - 做什麼：首次打開彈出隱私政策與用戶協議；記錄微信身份；根據角色決定「我的」頁是否顯示管理入口
  - 對應：規格書「首次打開」「我的」、全局規則 G7
  - 完成標準：普通微信號找不到任何管理入口
- [ ] **T4 老闆和員工綁定**
  - 做什麼：老闆初始化二維碼和手機號備用路；員工邀請二維碼（10 分鐘、一次性）；移除員工
  - 對應：規格書「管理端 · 老闆綁定」「員工管理」
  - 完成標準：規格書「員工管理」的 4 條驗收標準全部通過

## 階段 2 · 訂場核心

上一版 bug 最多的地方，每個任務都要認真測完再往下。T9 需要微信支付商戶號已綁定小程序；未綁好之前先用模擬付款開發。

- [ ] **T5 營業時間和價格計算**
  - 做什麼：日常營業時間、特殊日期、全天休息；常用價格（含生效日期）和單日價格；算出 7 個營業日
  - 對應：規格書「價格與營業時間」、澄清 B6
  - 完成標準：23:30 打開日期條從明天起；設了全天休息的日子不出現；單日價格優先於常用價格
- [ ] **T6 訂場首頁表格**
  - 做什麼：日期條、場地 × 時段表格（凍結場地號和時間）、5 種格子狀態、橫幅位置
  - 對應：規格書「訂場首頁」、全局規則 G1、G5
  - 完成標準：規格書「訂場首頁」6 條驗收標準全部通過
- [ ] **T7 購物車**
  - 做什麼：圓形浮窗和角標；購物車頁；手機緩存；失效項目和「清除失效项」；價格變動彈窗
  - 對應：規格書「購物車」、澄清 B3、B4、C4
  - 完成標準：規格書「購物車」驗收標準全部通過
- [ ] **T8 下單和防重複賣**
  - 做什麼：退款規則彈窗；手機號和通知授權；檢查格子與庫存；「場地佔用」整單鎖定；同時只能一張待支付
  - 對應：規格書「下單、待支付與支付結果」、技術方案「關鍵機制 1」、澄清 C1
  - 完成標準：兩部手機同時搶同一格，只有一部成功
- [ ] **T9 微信支付和待支付頁**
  - 做什麼：向微信下單（5 分鐘有效期）；接收付款通知；待支付頁倒計時、醒目的取消按鈕；支付結果頁
  - 對應：規格書「下單、待支付與支付結果」、技術方案「關鍵機制 3」
  - 完成標準：第 4 分 59 秒付款成功，訂單成立；按「取消订单」後格子立即恢復可訂
- [ ] **T10 到期處理和三道防線**
  - 做什麼：到期查單、向微信關單、放出場地；逾期付款自動全額退款；每分鐘定時對帳
  - 對應：立項書「訂單關閉的定義」「超時付款的處理」、技術方案「關鍵機制 2、4」
  - 完成標準：5 分鐘不付，格子恢復可訂、訂單變「已關閉」；模擬逾期付款，錢自動退回

## 階段 3 · 訂單與退款

- [ ] **T11 我的訂單和訂單詳情**
  - 做什麼：個人資料（頭像暱稱或隱藏手機號）；訂單按狀態分頁；待支付卡片帶倒計時和兩個按鈕；每格場地、每種商品一張卡片
  - 對應：規格書「我的」、澄清 A1、A3、B2
  - 完成標準：混合訂單在「全部」「待使用」都找得到；訂 2 小時顯示 2 張卡片
- [ ] **T12 客人自助退款**
  - 做什麼：每張卡片的「退款」；開場前 15 分鐘規則；確認彈窗；商品選張數退；唯一退款單號防重複退
  - 對應：規格書「我的 · 訂單詳情」、技術方案「關鍵機制 4」
  - 完成標準：開場前 14 分鐘「退款」變灰；退 1 張券只退 1 張的錢；網絡中斷重試不會退兩次

## 階段 4 · 活動商品

- [ ] **T13 商品管理（管理端）**
  - 做什麼：新增和編輯商品（含固定日期活動的開始時間）、上下架、已售不能刪
  - 對應：規格書「商品管理」、澄清 B8
  - 完成標準：規格書「商品管理」驗收標準全部通過
- [ ] **T14 活動頁和商品詳情**
  - 做什麼：長方形卡片列表、列表直接加購、詳情頁底部懸浮欄、立即購買
  - 對應：規格書「活動」
  - 完成標準：規格書「活動」驗收標準全部通過
- [ ] **T15 券碼和核銷**
  - 做什麼：每張訂單每種商品一個券碼；核銷頁掃碼或輸碼、選張數；核銷記錄和當天撤銷；固定日期活動過期自動退款
  - 對應：規格書「我的 · 訂單詳情」「核銷」
  - 完成標準：×3 的券核銷 2 張後顯示「可用 1 张」；前一天的記錄不能撤銷

## 階段 5 · 管理端

- [ ] **T16 訂單管理**
  - 做什麼：搜索手機號後 4 位或訂單號；篩選；查看電話留痕並可撥打；任何時候退款、部分金額、多選合併退款；50 次限制提示；兩人同時退只退一次
  - 對應：規格書「訂單管理」、澄清 C2
  - 完成標準：規格書「訂單管理」驗收標準全部通過
- [ ] **T17 場地管理（鎖場）**
  - 做什麼：同一表格點格子鎖定或解鎖、多選；已訂和待支付的格子不能鎖
  - 對應：規格書「場地管理」、澄清 C3
  - 完成標準：規格書「場地管理」驗收標準全部通過
- [ ] **T18 價格與營業時間頁**
  - 做什麼：常用價格、單日價格（逐天選或選一段、滾動勾選場地、衝突和超出營業時間檢查）、價格預覽；日常營業時間和特殊日期
  - 對應：規格書「價格與營業時間」、澄清 A4、C5
  - 完成標準：價格預覽與客人訂場頁完全一致
- [ ] **T19 橫幅管理和首頁輪播**
  - 做什麼：最多 5 張、拖動排序、三種跳轉、長期和限時顯示
  - 對應：規格書「橫幅管理」
  - 完成標準：規格書「橫幅管理」驗收標準全部通過
- [ ] **T20 報表和導出 Excel**
  - 做什麼：按日、按月；收入、退款、實收；使用率；熱門時段；導出
  - 對應：規格書「報表」、澄清 B7
  - 完成標準：手算一天的收入與報表一致；Excel 與頁面一致
- [ ] **T21 員工管理頁**
  - 做什麼：員工卡片列表、改備註名、新增（產生邀請二維碼）、移除
  - 對應：規格書「員工管理」
  - 完成標準：老闆能看到所有員工並改備註名
- [ ] **T22 通知**
  - 做什麼：企業微信群機器人推送新訂單和退款（手機號隱藏中間 4 位）；管理端紅點；客人「超時已退款」通知
  - 對應：規格書「通知」、澄清 E1
  - 完成標準：一筆新訂單付款後，群裡收到消息、紅點 +1

## 階段 6 · 測試與上線

- [ ] **T23 註銷帳號和個人資料自動刪除**
  - 做什麼：自助註銷；最後一次訂場 1 年後自動刪除手機號；舊訂單顯示「已注销用户」
  - 對應：規格書「我的 · 其他入口」、澄清 C6
  - 完成標準：註銷後管理端仍看得到訂單金額，但看不到手機號
- [ ] **T24 全面驗收**
  - 做什麼：逐條過一遍規格書所有驗收標準和全局規則 G1–G9；在蘋果和安卓真機上各試一次；用真錢小額（例如 ¥0.01 的測試價）走完付款和退款
  - 完成標準：所有驗收標準打勾；測試價改回正式價格
- [ ] **T25 提交審核和發布**
  - 做什麼：確認上線清單全部完成（備案、隱私指引、支付綁定、企業微信群）；提交微信審核；審核通過後發布；把老闆碼交給唐先生
  - 完成標準：客人能在微信搜到「飞翔球馆」並完成一次真實訂場

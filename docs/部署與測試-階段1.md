# 部署與測試 · 階段 1（T1–T4）

本文件教你把階段 1 的程式放上雲開發並逐項測試。照順序做，每一步做完再往下。

## 一、準備

1. 用微信開發者工具「導入項目」，選這個倉庫的資料夾，AppID 已填好 `wxffe19c5443bb0f36`
2. 打開 `miniprogram/config.js`，把 `REPLACE_WITH_ENV_ID` 換成你的**雲開發環境 ID**（例如 `cloud1-xxxxxxx`），保存

## 二、上傳雲函數

在開發者工具左側 `cloudfunctions` 資料夾裡，對 `user`、`staff`、`initdb` 三個資料夾**逐個**右鍵 →「上傳並部署：雲端安裝依賴」。看到「上傳成功」即可。

## 三、初始化數據庫（只做一次）

1. 打開「雲開發」控制台 →「雲函數」→ 找到 `initdb` →「雲端測試」
2. 參數填 `{}`，點「運行測試」
3. 返回結果有 `"ok": true` 即成功；到「數據庫」能看到 16 個集合

## 四、設定權限

1. **數據庫**：逐個集合 →「數據權限」→ 選「自定義安全規則」，填：
   ```json
   { "read": false, "write": false }
   ```
   （小程序前端不直接讀寫數據庫，全部經雲函數，這樣最安全）
2. **雲存儲** →「權限設置」→ 選「所有用戶可讀，僅創建者可讀寫」（頭像、邀請二維碼要能顯示）

## 五、綁定老闆

**主路：老闆碼**

1. 雲開發控制台 →「雲函數」→ `staff` →「雲端測試」，參數填：
   ```json
   { "action": "createOwnerInvite" }
   ```
2. 結果裡的 `qrFileId` 是二維碼圖片，到「雲存儲」的 `invites/` 資料夾找到同名圖片下載，發給老闆
3. 老闆用微信掃碼 → 小程序打開「身份綁定」頁 → 顯示「绑定成功，你已成为老板」
4. 碼 24 小時有效、只能用一次

**備用路：手機號**

1. 雲開發控制台 →「數據庫」→ `settings` → 記錄 `owner` → 把 `presetPhone` 改成老闆的手機號
2. 老闆打開小程序、授權這個手機號 → 自動成為老闆；`presetPhone` 隨即清空

> 小程序正式發布前，二維碼打開的是「開發版」，掃碼的人必須是小程序的開發者或體驗成員。正式發布後，到 `staff` 雲函數的「環境變量」加上 `QR_ENV_VERSION = release`。

## 六、逐項測試

測試時建議先用自己的微信當老闆，再找一個朋友的微信當員工、一個當客人。

**T1 項目骨架和公共樣式**
- [ ] 底部「订场／活动／我的」3 個分頁可切換
- [ ] 把手機時間調快 1 小時，重新打開，「員工管理」裡的加入時間不變

**T2 數據庫和權限**
- [ ] 16 個集合都已建立，權限都是自定義規則 `read: false, write: false`

**T3 登入、隱私協議和身份識別**
- [ ] 第一次打開彈出協議彈窗；不勾選直接按「同意并继续」會提示要先勾選
- [ ] 同意後接著出現「授权手机号」，按「暂不授权」也能進去瀏覽
- [ ] 普通微信號在「我的」頁找不到「管理后台」
- [ ] 「我的」頁點頭像可換微信頭像、點名字可改暱稱；未設定時只顯示中間 4 位隱藏的手機號

**T4 老闆和員工綁定**
- [ ] 老闆掃老闆碼後，「我的」頁出現「管理后台」，側邊欄看得到全部 8 項
- [ ] 老闆在「員工管理」按「+ 新增员工」出現二維碼，顯示倒計時
- [ ] 員工掃碼後，「我的」頁出現「管理后台」，側邊欄只有核銷、訂單、場地、商品、橫幅 5 項
- [ ] 同一個二維碼第二個人掃，提示「邀请码已失效，请联系老板重新生成」
- [ ] 二維碼產生 10 分鐘後再掃，提示已失效
- [ ] 老闆改員工備註名、移除員工後，頁面不跳回頂部
- [ ] 移除後，該員工重新打開小程序看不到管理入口

全部打勾後，在 `docs/05-任務清單.md` 把 T1–T4 勾上，進入階段 2。

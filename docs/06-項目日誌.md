## 2 怎麼跟這位用戶配合（很重要）

- 用戶田問是**編程小白**：**一律用繁體中文、白話**，不講術語；操作要一步一步說明點哪裡。
- **規矩：做任何修改前，先說明打算怎麼做，等用戶同意了才動手。**
- 回覆簡短，結論先行；做完一件事說清楚「改了什麼、他要做什麼」。
- 用戶在 Windows 電腦用**微信開發者工具**，在真機上測試（模擬器不支持隱私相關的系統彈窗，所以「授權手機號、選圖」要在手機預覽或遠程調試裡測）。
- 他有時會手誤或說得簡略（例如「後臺的訂單管理不需要」是打錯字）；不確定時用選擇題問，比猜好。
- 更新程式的標準流程（他常因覆蓋舊資料夾弄成舊版）：**重新下載最新 ZIP → 解壓到全新資料夾 → 微信開發者工具「導入項目」（後端服務選微信雲開發）**；改了雲函數要右鍵「上傳並部署：雲端安裝依賴」。
- 提交規範：提交訊息中文；結尾加 Co-Authored-By 和 Claude-Session 行；每次改完跑 `node tests/run.js`，全過才推送。

## 10 踩過的坑（不要重複）

- **上傳圖片、授權手機號點了沒反應**：不是程式問題，是後台「用戶隱私保護指引」沒聲明對應權限（錯誤碼 errno 112）。
- **覆蓋舊資料夾變回舊版**：Windows 資料夾巢狀、文件被佔用；一律用全新資料夾 + 導入項目。
- **改了雲函數沒生效**：必須重新「上傳並部署：雲端安裝依賴」；前端有 fallback，但 `lines`、`fee` 等新欄位要部署後才有。
- **新訂單才有各項金額（`lines[].fee`）**：部署前下的單、舊訂單都不會拆卡片。
- **改 wxss 時 python 腳本誤刪規則**：改樣式後務必看一眼 diff。
- **表格高度**：訂場頁和後台場地管理都要在內容渲染完之後才量高度（`measure()`），否則會比螢幕長或最後一行被蓋住。
- **模擬器 callFunction 報 -601002**：是網絡，重試或 Ctrl+R。
- **測試輸出的 "socket hang up" / "delayed network failure"**：是測試故意模擬的故障，不是錯誤；看最後一行「全部通過」。

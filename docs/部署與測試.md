# 部署與測試（全部階段）

本文件教你把整個小程序放上微信雲開發並逐項測試。照順序做，每一步做完再往下。
階段 1 的細節（老闆綁定、員工測試）見《部署與測試-階段1》。

## 一、雲函數一覽

| 雲函數 | 用途 | 需要的設定 |
| --- | --- | --- |
| `user` | 登入、同意協議、手機號、頭像暱稱、註銷 | — |
| `staff` | 老闆碼、員工邀請碼、員工管理 | 環境變量 `QR_ENV_VERSION`（上線後設為 `release`） |
| `booking` | 客人端：訂場表格、購物車、下單、付款、我的訂單、退款、活動、券碼 | 環境變量 `MCH_ID`、`WECOM_WEBHOOK`、`TPL_TIMEOUT_REFUND`、`TPL_TIMEOUT_REFUND_FIELDS` |
| `admin` | 管理端：核銷、訂單、鎖場、商品、橫幅、價格、營業時間、報表 | 同上 |
| `payNotify` | 微信支付結果通知（付款成功時由微信調用） | 同上 |
| `timer` | 定時任務：每分鐘處理到期訂單、對帳、場地已使用、活動過期退款；每天 3 點刪除過期手機號 | 同上；上傳後要「上傳觸發器」 |
| `initdb` | 初始化數據庫（只執行一次） | — |

`_shared` 資料夾**不是雲函數**，不用上傳。它是公共代碼，已複製到 `booking`、`admin`、`timer`、`payNotify` 的 `lib/` 裡。以後修改 `_shared` 裡的檔案後，要在項目根目錄執行 `node scripts/sync-shared.js`，再重新上傳這 4 個雲函數。

## 二、上傳

1. `miniprogram/config.js` 填好 `CLOUD_ENV`（雲開發環境 ID）
2. 在開發者工具裡，對 `user`、`staff`、`booking`、`admin`、`payNotify`、`timer`、`initdb` **逐個**右鍵 →「上傳並部署：雲端安裝依賴」
3. 對 `timer` 再右鍵 →「上傳觸發器」（每分鐘自動執行）
4. 執行 `initdb`（見《部署與測試-階段1》第三步），會建立 14 個集合
5. 設定數據庫和雲存儲權限（見《部署與測試-階段1》第四步）

## 三、環境變量（雲開發控制台 → 雲函數 → 選函數 →「版本與配置」→「環境變量」）

`booking`、`admin`、`payNotify`、`timer` 四個函數都要填**同樣**的值：

| 名稱 | 填什麼 | 不填會怎樣 |
| --- | --- | --- |
| `MCH_ID` | 微信支付商戶號（10 位數字） | 走「模擬支付」：付款時彈出測試用的確認框，不扣真錢 |
| `WECOM_WEBHOOK` | 企業微信群機器人的完整地址 | 不發群消息，只有管理端紅點 |
| `TPL_TIMEOUT_REFUND` | 「超时已退款」訂閱消息模板 ID | 不給客人發通知 |
| `TPL_TIMEOUT_REFUND_FIELDS` | 模板裡「說明」和「金額」兩個字段的名稱，用逗號分隔，例如 `thing1,amount2` | 默認用 `thing1,amount2` |

客人端的模板 ID 也要填到 `miniprogram/config.js` 的 `TPL_TIMEOUT_REFUND`，客人下單時才會請求授權。

### 接通真實微信支付

1. 微信支付商戶平台：商戶號關聯小程序 AppID
2. 雲開發控制台 →「設置」→「其他設置」→「微信支付配置」：添加商戶號，按提示在商戶平台確認授權（含**退款**權限）
3. 4 個函數填好 `MCH_ID`，重新上傳一次
4. 用 ¥0.01 的單日價格測試一次真實付款和退款，再改回正式價格

## 四、逐項測試

建議準備 3 個微信：老闆、員工、客人。每項打勾後在《05-任務清單》把對應任務勾上。

**T5 營業時間和價格**
- [ ] 晚上 23:00 後打開，日期條從明天起，仍有 7 天
- [ ] 營業時間 → 特殊日期設某天「全天休息」，日期條跳過那天
- [ ] 設一條單日價格，訂場頁該格顯示新價格；價格預覽與訂場頁一致

**T6 訂場首頁**
- [ ] 5 種格子狀態顏色和文字正確；滑動時場地號和時間始終可見
- [ ] 選格、取消、切換日期，表格停在原位置
- [ ] 另一部手機下單未付款時，15 秒內本機該格變「不可订」

**T7 購物車**
- [ ] 訂場頁和活動頁右下角都有浮窗，件數正確；關掉小程序再打開，購物車還在
- [ ] 購物車裡的格子被別人訂走後顯示「已失效」，不計入合計；「清除失效项」可清掉
- [ ] 加入購物車後老闆改價，按「去结算」先彈出「以下价格已变动」

**T8–T10 下單、付款、到期**
- [ ] 有場地時先彈退款規則；未授權手機號時要求授權，拒絕則提示並停止
- [ ] 兩部手機同時結算同一格，只有一部成功
- [ ] 關掉付款窗後停在待支付頁，5 分鐘倒計時；「取消订单」醒目，按下後格子立即可訂
- [ ] 5 分鐘不付，訂單變「已關閉」，格子恢復可訂
- [ ] 已有一張待支付訂單時再結算，提示「你有一笔待支付订单」
- [ ] 付款成功後購物車裡已買的項目自動消失；企業微信群收到新訂單消息

**T11–T12 我的訂單和退款**
- [ ] 訂單按「全部／待支付／待使用／已完成／退款」分頁；混合訂單在「全部」和「待使用」都找得到
- [ ] 訂 2 小時顯示 2 張卡片；開場前 14 分鐘「退款」變灰
- [ ] 買 3 張券顯示一張「×3」卡片，退 1 張只退 1 張的錢

**T13–T15 活動商品和核銷**
- [ ] 新增商品、上下架；已售出的商品不能刪除
- [ ] 活動頁一行一張卡片，列表可直接加購；詳情頁底部懸浮欄
- [ ] 點商品卡片看券碼（二維碼 + 6 位數字）；員工掃碼或輸碼後選張數核銷
- [ ] 當天核銷記錄可撤銷，前一天的不行；撤銷後記錄裡看得到兩筆

**T16–T22 管理端**
- [ ] 訂單管理：手機號後 4 位能搜到；「查看电话」每按一次都留記錄；開場後仍能退款；部分金額退款；多選合併退款
- [ ] 場地管理：多選格子一次鎖定；已訂和待支付的格子鎖不了
- [ ] 價格：常用價格立即／指定日期生效；單日價格逐天選、選一段、滾動勾選場地；重疊或超出營業時間時不能保存
- [ ] 營業時間：縮短時段如已有訂單，提示並列出訂單
- [ ] 橫幅：最多 5 張；三種跳轉；限時橫幅到時自動出現和消失
- [ ] 報表：手算一天收入與報表一致；導出 Excel 數字與頁面一致
- [ ] 新訂單或退款後，管理端左上角選單出現紅點，打開「订单管理」後消失

**T23 註銷**
- [ ] 有未使用的場地或券時不能註銷
- [ ] 註銷後管理端該訂單顯示「已注销用户」，看不到手機號

## 五、實作備註（與規格書的差異，請確認）

1. **橫幅排序**：規格寫「可拖動調整順序」，目前做成每張橫幅旁的「↑ ↓」按鈕，老人家更容易按準。如需真正拖動再改。
2. **管理端紅點**：目前是「上次打開訂單管理之後的新消息數」，打開訂單管理即清零；不是逐條標記已讀。
3. **待支付期間客人主動取消**：微信規定下單 5 分鐘內不能關單，所以取消時先放出場地，5 分鐘後由定時任務向微信正式關單；萬一這期間仍付了款，會自動全額退款。
